# SPEC-003: Phase 2 全自动 + 工作流

## 前提
Phase 1 对茶2、茶4、熟4分别完成 SPEC-002 金标和连续实机验收；录像数据 >100 局。逐模式核对识牌、规则门禁和建议，错误高置信建议必须单列且为 0。仅有合并后的“识牌准确率 >90%”不足以授权自动点击；低置信或状态不明时须弃权。

## 目标
从"辅助"到"全自动"，再到"自用工作流"（2026-10-20 用户亲口澄清：代打仅自用，非对外业务）

## 功能清单

### 1. 全自动代打
- **触发**：用户按"开始代打"，bot 接管本账号（自用）
- **循环**：
  1. ADB 截图 → 识牌（手牌+牌池+副露）
  2. TeaBot.think() → 决策（打哪张/吃碰杠胡过）
  3. 动作门禁：确认当前玩法、财神／红中规则、手牌与建议均可信；低分、歧义、无框、规则不可读或坐标无法复核时停止点击
  4. 坐标映射：牌 → 屏幕坐标（G3），点击前复核目标牌和画面状态
  5. ADB tap 执行（G4），点击后重新截图确认状态变化；未确认时停止
  6. 记录决策 JSONL；结算记录格式见下文
  7. 检测回合结束 → 下一局
- **停止条件**：打完一间（16 局）即停，不擅自开房
- **红线**：房卡=0 立即停；识别“邀请您进入”且定位“取消”后只点“取消”并复核，不点“确定”；其他弹窗按类型另定动作，未知弹窗停止；ANR 仅在确认对应提示后点“等待”

### 2. 副露检测（G6）
- 识别已吃/碰/杠的牌（屏幕中部区域）
- 按茶／熟各自已验证的起手张数和副露形式更新手牌数；茶闭手现有入口为 16／17 张，不得把 `13-3*副露数` 套给全部玩法。熟的副露后张数另用实机样本核定
- 影响向听计算

### 3. 结算 OCR（G7）
- 识别结算画面的得分（数字模板 0-9、+/-）
- Phase 1 `assist_record/v4` 保持原契约。结算数据在实现前定义 `v5` 或独立结算事件，明确与 `decision_id`／`round` 的关联；不向 v4 行临时加 `settle` 字段
- 验证：与实际得分一致

### 4. 自用工作流（2026-10-20 用户亲口澄清：代打仅自用，非对外业务；原"业务工作流/代打订单"口径作废）
- **触发**：用户自己开好房间/进入对局后按"开始代打"，bot 接管本账号；打完一间（16 局）即停，不擅自开房
- **自用记录**：每局记录（时间/房间/结果/得分）到 JSONL，生成个人日报供自我复盘（非客户记账/结算）
- **自我风控**：连续输 X 局暂停；单日上限；异常截图告警（保护自己账号，非客户 SLA）
- **风险口径**：自用仍是本账号跑 bot，游戏方封禁风险客观存在；不再按"代打工作室业务"评估风险

## 技术要点
- G3 坐标映射：牌在手牌区的 X 坐标 = f(牌序)，需实测校准；每次点击前核对当前截图的目标框
- G4 点击：ADB tap，点后截图验证；错误点击次数作为单独验收项
- 延迟：整回合 <5 秒（截图 2s + 识牌 0.5s + 决策 0.1s + 点击 0.5s）
- 稳定性：连续 16 局不崩，断线重连

## 验证
1. 模拟对局：dry-run 模式跑 10 局，决策正确
2. 实机：1 间（16 局）全自动完成，无人工干预
3. 结算 OCR 准确率 >95%
4. 异常情况（弹窗/断线/房卡空）正确处理
5. 三模式分别报告错误高置信建议和错误点击次数；任一未识别或规则不明场景不得自动点击

## 不做
- 多开（一次只打一间）
- 自动充值/买房卡
- 其他游戏/其他玩法
