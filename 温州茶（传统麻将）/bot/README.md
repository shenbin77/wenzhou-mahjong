# 温州茶／熟本地辅助

支持温州茶 4 人、温州茶 2 人、温州熟 4 人三个推荐入口。茶与熟是同一客户端的同一套画面和麻将牌，识牌共用 `tile_vision.py`；三种模式的画面人数与玩法规则分别核对。当前只有温州茶 2 人接通全自动代打，另外两种保持只读推荐，等待各自实机验收。

双击桌面“温州麻将辅助器”快捷方式启动同一个主窗口。左侧显示本次抓到的游戏画面和识牌框，右侧显示手牌、财神、建议、阶段与异常。底部日志始终展开并用绿/橙/红区分已验证动作、等待/弃权和停手/错误。

1. 启动器会为每个在线雷电自动打开一个固定设备窗口；无需查找、填写或刷新 serial。选择玩法并填写本地账号标记（例如游戏昵称“玉姐”），点“连接并绑定”，再点“开始跟随”。开始跟随后会自动核对牌桌玩法；只读推荐阶段不点击游戏。
2. 核对实时识牌和推荐正常后，温州茶 2 人可再点“开启全自动代打”。BOT 接管出牌、过和通过安全门禁的鸣牌；任一证据不足就弃权或停手并写日志。开始游戏、结算、离桌、充值和分享永久不自动点击。
3. “离线预检”移入“更多”，只用于旧截图链路检查，不能作为当前牌局依据。
4. 主窗口左侧看原图和识牌框（绿=已接受预测、橙=未识别、红=建议牌），右侧看财神、手牌、建议与暂停原因。茶的财神优先从“财”角标读出；看不清时才手选。每帧处理完约 0.25 秒后再抓下一帧，实际周期取决于 ADB 与识牌耗时。
5. 需要逐帧查历史、人工纠错时，再开“更多 → 历史逐帧复核”。纠错记录另存；需要重新算牌时用“修正手牌并重算”。修正基于旧画面时仍会标注“非实时”，不能当作当前对局建议。“导入截图”和“导入录像复核”也可在打牌前使用，不要求连接模拟器。

固定状态条会常显绑定账号、设备、当前阶段和最新问题；底部日志保存每次门禁、弃权、建议、动作和停手原因。实时推荐超过 3 秒没有新帧会撤回建议；全自动运行中由同一代打循环输出分析帧和台账，不再并发启动第二套截图循环。

已有 MP4 可在“更多 → 导入录像复核（每秒1帧）”中选择。它按当前选定玩法抽帧识别，复核窗同步跟随；按“停止录像复核”可提前结束。原录像不改动，所有已抽取帧都保存，画面玩法不符会弃权。这个功能检查每个**抽取并识别的帧**，不是逐帧检查视频原始帧率。

连续观察自动保存每张已抓取的原图，并把每次识别的框、牌名、分数、弃权原因和疑点追加到本次会话的 `recognition_audit.jsonl`；识别抛错也留下该帧及错误记录。复核窗口直接在原图上画框，不额外保存一份标注图。人工判断另存 `recognition_reviews.jsonl`；决策稳定记录仍在 `assist_record.jsonl`，它不代表逐帧真值。自动疑点可发现漏识、数量异常及接近识牌接受阈值的牌；这些只是复核提示，不会改变识牌决策。没有人工或独立标注时，未标记的帧也不能算已验证正确。已测一个 1600×900 建议帧约 1.9 MB；按每秒一帧约 6.7 GB/小时，长时间运行请留意 D 盘空间并在不用时点“停止”。窗口显示上一帧结果时会标明“正在复核下一帧”，不把它当成新帧建议。

茶 2 人和茶 4 人分别要求截图明确写有对应人数与“无中发”；熟 4 人要求“放炮麻将”及四人规则。茶 4 人的旧回放 `323028/r01/frame_01.png`、`frame_02.png` 已离线得到 16 张等待摸牌与 17 张牌效率建议，但未验证四人胡牌计分、河牌风险及真实对局；遇到四人胡牌会暂停建议。暗牌、遮挡、未识全或不支持的牌也会暂停。财神模板仍有真实样本缺口，识别失败可人工核对后选择。茶 2 人已有真实自动动作证据，但完整 16 局零人工验收未通过；茶 4 人、熟 4 人仍保持只读推荐。离线回放和预检不能替代真实对局证据。

已核的两个 2 人茶房间（833667、984226）都写“无中发”，当前入口要求截图同时看清“2人”和“无中发”才给建议；规则文字被牌挡住也会暂停。手工修正必须关联同一张可核规则的截图。用户确认茶另有普通红中牌；对应房间尚无已核回放和识牌模板，不能将这类房间误判为当前已支持的“无中发”规则。茶财神每局翻定，与熟固定红中财神不同。
