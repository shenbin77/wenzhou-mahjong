# 温州茶／熟本地辅助

支持温州茶 4 人、温州茶 2 人、温州熟 4 人三个入口。茶与熟是同一客户端的同一套画面和麻将牌，识牌共用 `tile_vision.py`；三种模式的画面人数与玩法规则分别核对。本地辅助只读画面，不连接游戏服务器。

双击桌面“温州麻将辅助器”快捷方式启动同一个主窗口。左侧显示本次抓到的游戏画面和识牌框，右侧显示手牌、财神、建议、暂停原因与延迟；只读画面，不替你点击游戏。窗口会明确区分“实时跟随中”“已停止”“离线预检（旧截图）”和“导入截图（非实时）”，旧截图不会套用实时 3 秒过期判断，也不会被当成当前对局建议。

1. 打牌前选目标玩法，点“离线预检”。主窗口用项目里保存的该玩法截图跑完整识牌与建议链路，不连接模拟器；标题明确标记“旧截图”，结果不是当前牌局，也不代表人工核准了每张牌。此时建议区灰显并持续标注，不参与实时过期判断；点“开始跟随”后会等待第一张实时画面来替换它。
2. 进入真实对局后，先核对眼前牌局与顶部所选玩法一致，再填写“账号标记（必填）”，并勾选“已核对本局玩法”。这个勾选只代表玩法核对，不代表识牌或建议已核准；账号标记只是本地记录标记，不是游戏账号。两项都满足后辅助器才会自动开始跟随，也可以手动点“开始跟随”。按钮运行中变成“停止跟随”，停止后最后一帧的旧建议会立即失效。
3. 主窗口左侧看原图和识牌框（绿=已接受预测、橙=未识别、红=建议牌），右侧看财神、手牌、建议与暂停原因。茶的财神优先从“财”角标读出；看不清时才手选。每帧处理完约 0.25 秒后再抓下一帧，实际周期取决于 ADB 与识牌耗时。
4. 需要逐帧查历史、人工纠错时，再开“更多 → 历史逐帧复核”。纠错记录另存；需要重新算牌时用“修正手牌并重算”。修正基于旧画面时仍会标注“非实时”，不能当作当前对局建议。“导入截图”和“导入录像复核”也可在打牌前使用，不要求连接模拟器。

状态以主状态栏和左侧标题为准：勾选但账号为空时显示“账号标记为空”，不会自动开始；开始后等待第一张实时画面时显示“实时跟随 · 等待当前画面”；正常跟随时为“实时跟随 · 当前截图”；停止后显示“已停止跟随”，最后一帧建议立即失效。实时跟随超过 3 秒没有新帧会变红并撤回建议；离线预检和导入截图不会触发这条实时过期警告。按“下一局”会停止跟随并保留“已核对本局玩法”勾选，但会提示重新核对玩法与财神。实时条件下仍只显示建议，不点击、不代打。

已有 MP4 可在“更多 → 导入录像复核（每秒1帧）”中选择。它按当前选定玩法抽帧识别，复核窗同步跟随；按“停止录像复核”可提前结束。原录像不改动，所有已抽取帧都保存，画面玩法不符会弃权。这个功能检查每个**抽取并识别的帧**，不是逐帧检查视频原始帧率。

连续观察自动保存每张已抓取的原图，并把每次识别的框、牌名、分数、弃权原因和疑点追加到本次会话的 `recognition_audit.jsonl`；识别抛错也留下该帧及错误记录。复核窗口直接在原图上画框，不额外保存一份标注图。人工判断另存 `recognition_reviews.jsonl`；决策稳定记录仍在 `assist_record.jsonl`，它不代表逐帧真值。自动疑点可发现漏识、数量异常及接近识牌接受阈值的牌；这些只是复核提示，不会改变识牌决策。没有人工或独立标注时，未标记的帧也不能算已验证正确。已测一个 1600×900 建议帧约 1.9 MB；按每秒一帧约 6.7 GB/小时，长时间运行请留意 D 盘空间并在不用时点“停止”。窗口显示上一帧结果时会标明“正在复核下一帧”，不把它当成新帧建议。

茶 2 人和茶 4 人分别要求截图明确写有对应人数与“无中发”；熟 4 人要求“放炮麻将”及四人规则。茶 4 人的旧回放 `323028/r01/frame_01.png`、`frame_02.png` 已离线得到 16 张等待摸牌与 17 张牌效率建议，但未验证四人胡牌计分、河牌风险及真实对局；遇到四人胡牌会暂停建议。暗牌、遮挡、未识全或不支持的牌也会暂停。财神小牌现有 31 种回放模板，尚缺二筒；识别失败可人工核对后选择。三种玩法的真实对局验收与自动代点均尚未完成；离线回放和预检不能替代真实对局证据。

已核的两个 2 人茶房间（833667、984226）都写“无中发”，当前入口要求截图同时看清“2人”和“无中发”才给建议；规则文字被牌挡住也会暂停。手工修正必须关联同一张可核规则的截图。用户确认茶另有普通红中牌；对应房间尚无已核回放和识牌模板，不能将这类房间误判为当前已支持的“无中发”规则。茶财神每局翻定，与熟固定红中财神不同。
